# Фаза 6 — перенос авторитета МАТЧА на сервер

Связанные документы: `docs/PHASE5_HANDOFF.md` (фаза 5 — движение/хитрег), `docs/DIFFERENCES.md`,
`CLAUDE.md` (таблица файлов + запуск).

## Зачем

Сейчас сервер (`server.js`) авторитетен **только по движению и хитрегу пуль**. Весь МАТЧ — раунды,
таймеры, счёт, HP, деньги, закупка, бомба, гранаты, падение — крутится **локально у каждого клиента**
(`src/rounds.js`, `src/game.js`), без синхронизации. В мультиплеере это значит: два игрока играют
**разные матчи**, которые лишь делят движение и урон пуль (у каждого свой раунд/счёт/деньги/бомба).

Цель Фазы 6: сервер — **единственный источник правды по матчу**, клиент — тонкий рендер. Как в оригинале
CS: сервер задаёт карту, гоняет раунды, владеет HP/экономикой/бомбой; клиент шлёт ввод/намерения и
рисует присланное состояние.

## Принцип переноса (важно — как с движением)

Движение мы вынесли в **общее ядро** (`sim-core.js`, dual-mode): сервер крутит авторитетно, клиент
предсказывает тем же кодом, соло — локально. Для матча делаем по аналогии, но с двумя отличиями:

1. **Match-state НЕ предсказывается и НЕ откатывается.** HP/деньги/фаза/счёт — это редкие дискретные
   изменения; клиент их просто **отображает** с лёгким сглаживанием (таймер тикает локально между
   апдейтами). Никакого reconciliation/rollback, как для позиции, — на порядок проще движения.
2. **Match-логика сильно завязана на DOM/HUD/аудио/эффекты** (в отличие от чистой математики движения).
   Поэтому «честное» общее ядро тут дороже. Прагматичный путь:
   - Сервер получает **свою headless-стейт-машину матча** (`src/match-core.js`, dual-mode, чистая —
     числа из ReGameDLL, без DOM). Логика портируется из `rounds.js`/`game.js`.
   - Клиент при подключении переходит в **«ведомый режим»**: перестаёт сам тикать раунд/HP/деньги, а
     **рисует `gstate` от сервера** (весь рендер/HUD/звук остаётся). Намерения (закупка, плант, дефьюз)
     шлёт серверу.
   - **Соло (нет сервера) — без изменений**: клиент крутит свою текущую логику. Это сохраняет основной
     режим проекта. Развилка — один флаг «есть авторитетный сервер?».

> Решение по архитектуре: НЕ тащить общий dual-mode core для всего матча сразу (дорого из-за связки с
> рендером). Сервер — отдельная чистая стейт-машина; клиент — «ведомый режим» поверх существующего кода.
> Общие куски (числа/таблицы урона/экономики) выносим в маленькие dual-mode модули по мере надобности
> (как `combat-core.js`).

## Протокол (дополнения)

**Сервер → клиент** — новый `gstate` (раз в ~100–200 мс или по изменению):
```
{ t:'gstate',
  map:'de_dust2', phase:'buy'|'live'|'over', roundTime, buyTime, round, scoreT, scoreCT,
  bomb:{ planted, site, timer, carrier } | null,
  me:{ team, alive, hp, armor, helmet, money, weapons:[ids], ammo:{...}, defuseKit },
  players:[ { id, alive, team } ]   // чужие: только публичное (живой/команда); поза — в snap
}
```
(Можно слить с `snap` или отдельным сообщением — отдельным чище: разные частоты.)

**Клиент → сервер** — намерения:
```
{ t:'buy', item }            // сервер валидирует деньги/команду/зону/фазу, выдаёт
{ t:'plant' } / { t:'defuse', on:bool }   // или вывести из позиции+E+hold на сервере
{ t:'knife', ... }           // нож переезжает на сервер (см. 6B)
```
Движение (`cmd`) и `shot` — без изменений.

## Меню / лобби под клиент-сервер

Стартовое меню (`viewer.html` `#overlay` → `#menu`: `#maplist`, `#btn-play`, `#settings`) сейчас
одиночное. Под клиент-сервер оно становится **лобби**:
- **Статус сервера:** подключён / соло / подключаемся / сервер недоступен. Сейчас `netConnect` молча
  падает в соло (`_ws.onerror` — no-op) — выводим это в меню (индикатор + кол-во игроков онлайн из
  `gstate`/`welcome`).
- **Адрес сервера:** поле ввода (по умолчанию `ws://<host>:8081`, как сейчас в `NET_URL`); кнопка
  «Подключиться». Без сервера — кнопка «Играть соло» (текущее поведение).
- **Информация о матче/карте:** карту объявляет **сервер** (`gstate.map`) — в лобби показываем имя карты,
  текущий раунд/счёт (если присоединяешься к идущему матчу), список игроков/команд. `#maplist` из
  «выбери карту» превращается в «карта сервера» (выбор карты — серверная настройка, не клиентская).
- **Подключение раньше выбора команды:** чтобы видеть лобби/статус до спауна, `netConnect` стоит звать
  **при открытии меню** (а не в `_chooseClass`), а `hello` слать после выбора команды (как сейчас). Тогда
  меню видит `welcome`/`gstate` заранее.

> **Подгрузка карты остаётся текущей.** Сервер лишь **называет** карту (`gstate.map`); ассеты грузит
> клиент существующим конвейером (`src/load.js`: `de_dust2.obj/.mtl` + hull). Менять загрузчик не нужно —
> только: (1) если `gstate.map` ≠ загруженной, клиент перегружает нужную карту тем же `load.js`; (2) пока
> карта одна (`de_dust2`) — это просто сверка имени. Серверный hull под карту уже грузится в `server.js`.

Wiring по шагам: индикатор статуса + имя карты из `gstate` появляются на **6A** (как только есть `gstate`);
полноценное лобби (игроки/команды/адрес/онлайн, ротация карт) — на **6E**.

## Порядок работ (слоями, каждый — проверяемо в двух вкладках)

### 6A — Раунды + счёт на сервере ✅ ГОТОВО
- `src/match-core.js` (dual-mode, чистый): стейт-машина `phase: warmup→buy→live→over→(restart)`, таймеры,
  `round`, `scoreT/scoreCT`, условия конца (время → CT; элиминация при обеих командах), `winner/reason`,
  **карта**. Тест `tools/net_match_test.js`.
- Сервер: `world.match`, `worldTickMatch` (тик + revive на старте раунда), `gameState` → шлёт `gstate`
  ~5×/с + мгновенно на смене фазы; `alive` на игрока (из `react die/spawn`).
- Клиент: `applyServerRound` (rounds.js) → `_netDriven`, фаза/таймер/счёт/баннер из `gstate`; `updateRound`
  → `_updateRoundDriven` (локально только тикает таймер для гладкости + рисует HUD со счётом); на смене
  номера раунда — `_localRoundReset` (респаун/HP/патроны, HP пока клиентский). Соло — без изменений.
  Бомба/плант **отключены** в MP до 6D.
- Меню: `#mp-status` (онлайн/подключение/недоступен + карта); `netConnect(false)` на старте (только
  статус), `netConnect(true)` в `_chooseClass` (join). Сервер не включает игрока в матч до `hello` (`joined`).
- **Проверка глазами:** обе вкладки видят один таймер/счёт/номер раунда/рестарт; меню показывает статус+карту.

> Осталось в interim до 6B: смерть/alive берётся из клиентского `react die` (доверие клиенту); HP/спаун
> ещё клиентские. Элиминация работает только при игроках в ОБЕИХ командах.

### 6B — HP / броня / смерть / респаун на сервере ✅ ГОТОВО
- `match-core.js`: `matchApplyDamage(pl, dmg, hg)` (кевлар по зоне — формула CS: половина в HP, остаток в
  броню; голова без шлема — мимо брони), `matchFallDamage(fallVel)`, `matchRevive(pl)`. HP/armor/helmet/
  alive — в `pl` на сервере. Тесты в `tools/net_match_test.js`.
- **Источники урона → сервер:** пули (`worldProcessShot` применяет к HP), нож (`{t:'hit'}` → сервер
  применяет, dmg по-прежнему от стрелка — interim), падение (`worldApplyCmd` ловит `ev.landed`). Дед не
  двигается (`worldApplyCmd` ранний выход при `!alive`).
- Сервер шлёт `{t:'dmg', id, hg, by, dealt, hp, died, w}` (broadcast) + `gstate.me` (HP/броня/alive
  per-recipient). Клиент: `applyServerSelf`/`onServerDamage` (game.js) — HP/смерть зеркалятся; remote
  флинч/смерть из `dmg`, revival из снапшота `al`. Локальный `playerTakeDamage` в MP — no-op; `react`
  протокол удалён (заменён на `dmg` + `al`).
- **Проверка глазами:** урон/HP/смерть/респаун сходятся у всех; элиминация по серверному HP.

> Осталось interim: **нож — dmg от стрелка** (доверие значению; геометрию сервер не проверяет); **гранаты
> HE / C4 / падение-в-MP от своих гранат** не применяются (локальный урон в MP отключён) — HE/C4 на 6D.
> **Kill feed UI** — ✅ сделан в 6E (использует поле `by`).

### 6C — Экономика + закупка ✅ ГОТОВО
- `match-core.js`: `MATCH_BUY` (каталог цена/команда/слот/тип — зеркало `BUY_CATALOG`), `matchBuy(pl,id)`
  (валидация деньги/команда/владение/капы + применение: оружие с заменой по слоту, кевлар/шлем, гранаты,
  дефуз-кит), `matchKillReward(w)` (нож $1500 / ствол $300), награды раунда (win $3250 / loss $1400).
  Деньги/инвентарь — в `pl` на сервере. Тесты в `tools/net_match_test.js`.
- Сервер: обработчик `{t:'buy',id}` (фаза buy + серверная зона `_inBuyZone` + `matchBuy`) → ответ
  `{t:'bought',ok,reason,...}`; награды за килл (в dmg-хендлерах) и за раунд (в `worldTickMatch`); экономика
  в `gstate.me` (money/weapons/nades/dk).
- Клиент: `buyItem` в MP шлёт интент; `applyServerSelf` зеркалит money/ownedWeapons/grenadeCounts/dk из
  `gstate.me`; `_onBought` — флеш + экип купленного оружия (оптимистично + ammo).
- **Проверка глазами:** деньги/закупка/инвентарь одинаковы у всех; нельзя купить без денег/вне зоны/не той
  командой; счёт денег растёт за киллы и раунды.

> Осталось interim: **гранаты и дефуз-кит** в MP не продаются (бросок/бомба ещё клиентские — 6D); докупка
> патронов в сети отключена; дроп старого ствола при ребае (pickups) в MP не воспроизводится.

### 6D — Бомба C4 на сервере ✅ ГОТОВО
- `match-core.js`: состояние бомбы в `ms.bomb` (`pos/site/timer/defuseProg/live`), фьюз `MATCH_C4_TIME=40`
  тикает в `matchTick` (фаза live; плант останавливает раунд-клок), детонация → T-победа + `ev.bombDetonate`,
  `matchBombPlant`/`matchBombDefuse` (CT-победа), `_matchCheckElim(joined, bombPlanted)` — пока бомба живёт,
  выбивание Т **не** заканчивает раунд (CT должны разминировать). `ms.bombResult` (`explode`/`defuse`) — кью клиенту.
  Числа зеркалят `rounds.js` (`PLANT_TIME=3`, `DEFUSE_TIME=10`, `DEFUSE_KIT=5`, `C4_DAMAGE=500`, `C4_RADIUS=700`,
  `PLANT_REWARD=800`). Тесты в `tools/net_match_test.js` (плант/детонация/дефьюз/элиминация).
- Сервер: носитель C4 — случайный живой T на старте раунда (`worldTickMatch`); `worldTickBomb` копит плант/дефьюз
  по геометрии (`_bombSiteAt`/`_nearBomb`, ±64 Z) из usercmd-флага `u` (E); `worldC4Damage` — радиус-урон с LOS
  (`sim.simTraceMove`, спад линейный, кевлар через `matchApplyDamage` hg=2) → `dmg`-события. `gstate.bomb` +
  `gstate.me.{c4,plantProg}`.
- Клиент (ведомый): `netRecordCmd` шлёт `u`; `_syncDrivenBomb` строит/чистит меш из `gstate.bomb` + кью
  (плант/взрыв/разминирование) по `bombResult`; `_updateRoundDriven` — бипы/блинк/сглаживание таймера;
  полоса плант/дефьюз (`#bomb-action`) теперь работает и в MP. `applyServerSelf` зеркалит `c4/plantProg`.
- **Проверка глазами:** плант/дефьюз/взрыв и победа по бомбе одинаковы во всех вкладках.

- ✅ **Дроп/подбор C4**: носитель погиб/отключился → бомба падает на землю (`world.droppedC4`, `_tickC4Carry`),
  любой живой T, подойдя вплотную (`_nearDrop`), автоматически подбирает (становится носителем). Клиент рисует
  лежащую C4 (`_syncDroppedC4` — коробка + оранжевый LED-маркер) из `gstate.dropC4`; на старте раунда и при планте
  чистится. Тест в `tools/net_match_test.js`.

> Осталось interim: визуала «несу бомбу» вне бомбсайта нет (только подсказка в зоне + LED у лежащей). Дефуз-кит/
> гранаты в MP — см. interim 6C.

### 6E — Команды / спауны / конфиг матча + полное лобби (⏳ частично)
- ✅ **Серверные спауны** (`server.js`): `_assignSpawns(world)` раздаёт КАЖДОМУ присоединившемуся игроку

- ✅ **Ростер + scoreboard + kill feed**: сервер считает K/D на игрока (`pl.kills/deaths` в `dmgEvent`),

  из `net.js _onDamage`, цвет по команде, авто-затухание 5с) и **scoreboard по Tab** (`_renderScoreboard` —
  две команды, K/D, кто жив, счёт раунда; своя строка подсвечена). `netMyId()` — подсветка себя. Прячется

- ✅ **Баланс команд**: меню выбора команды показывает состав (счётчики из `mpRoster`); нельзя встать в

- ❌ Осталось: поле адреса сервера в меню, **ротация карт** (бессмысленна — карта одна; нужен 2-й

  при джойне).

## Что сломается / на что смотреть

- **Большая поверхность:** `rounds.js`, `game.js`, частично `grenades.js`, `pickups.js`, `physics.js`
  (падение) завязаны на локальный авторитет. Каждый шаг — аккуратно перевести в «ведомый режим», не сломав
  соло.
- **Соло-режим must keep working** — главный режим проекта. Флаг «авторитетный сервер подключён?»
  (есть/нет `gstate`) разводит ветки: нет → текущая локальная логика, есть → ведомая.
- **Дубль чисел.** Числа матча/урона дублируются (клиент для соло + `match-core` для сервера). Держать в
  синхроне; где удобно — вынести в dual-mode модуль (как `combat-core`).
- **Таймеры.** Сервер шлёт оставшееся время; клиент тикает его локально между `gstate` и подравнивает по
  приходу (без рывков).
- **`react die/spawn` и клиентский `playerTakeDamage`** — на 6B становятся не нужны (сервер владеет
  смертью). Флинч можно оставить как визуальное событие от сервера.
- **Гранаты** — самое спорное по объёму: либо полноценная серверная симуляция снаряда, либо interim
  (владелец шлёт событие взрыва, сервер валидирует радиус-урон). Решить на 6B/6D.

## Рекомендованный старт

**6A (раунды+счёт)** — самый видимый эффект «общая игра» при наименьшем риске: не трогаем HP/экономику,
только переводим фазы/таймеры/счёт на сервер и клиент в ведомый режим. Дальше 6B (HP), 6C (деньги), 6D
(бомба), 6E (команды/карты).
